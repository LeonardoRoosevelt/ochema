### 契約與 DBML
1. **（中，事實）DBML 的長度限制沒有對應的驗證規則。** `schema.dbml` 寫 `headPlate varchar(32)`、`ownerName varchar(100)` 等，備註說「由 validation.ts 保證」，但 `checkPlate`／`validateRecordInput` 沒有任何長度檢查，features 也沒有長度規則；IndexedDB 不強制長度。結果是 DBML 宣稱的約束沒人實作。建議把四欄改成不帶長度（`varchar`／`text`），或明寫「長度僅為文件參考，不強制」。（DBML 驗收標準第 3 條「約束一致」的唯一缺口。）
2. **（低，事實）空檔案判定順序自相矛盾。** 製片人裁決與 Q3 寫「0 byte 回 EMPTY_FILE」，但 §4 注意事項 2 寫「前 4 bytes 不是 PK\x03\x04 一律 UNREADABLE」，0 byte 會先被這條攔成 UNREADABLE。features 的「完全空白的檔案」是「合法 xlsx 但工作表空白」，兩種做法都不違反 features，但契約要寫死順序（建議：長度 0 → EMPTY_FILE，再驗 PK，再 `XLSX.read` try/catch，再檢查工作表有無儲存格）。
3. **（中，意見）excel-export 的「那麼」無法只靠契約函式驗證。** 「匯出檔第一列標題依序為…」「沒有額外欄位」「儲存格的值是文字」需要看欄序、欄數、儲存格型態；`readWorkbook` 依標題名對應、忽略多餘欄、只回字串，無法證明欄序與「沒有額外欄位」。同理匯入情境要造「數字 7＋格式 000」「完全空白」「損毀」的 fixture，step definitions 必須直接用 SheetJS。契約開頭「step definitions 不直接碰 SheetJS」與此衝突。建議改成：測試用 helper（如 `tests/support/xlsx.ts`）可直接用 `xlsx` 造檔與讀回原始儲存格；正式程式碼才限定走 `excelRead.ts`／`excelWrite.ts`。
4. **（低，事實）「沒有可進行匯入的選項」沒有對應的資料層值。** 情境 `只有標題列、沒有資料列的檔案` 的第二個 Then 只能由 `counts.total === 0` 推得。可接受（這是 UI 規則），但 step 作者需知道要用 `counts.total` 判斷；也可在契約加一句。
5. **（低，意見）IndexedDB 實作陷阱，請在交接單提醒工程部。**
   - `createRecord`／`updateRecord`／`commitImport` 的交易內只能 await idb 的請求，夾進其他 await（例如動態 `import('xlsx')`）會使交易自動提交。
   - `add` 遇 `ConstraintError` 時交易會中止，`await tx.done` 也會 reject；沒有接住會變成 unhandled rejection，vitest 會把整個 run 判失敗。
   - `resetDbForTest` 要先 `db.close()` 再 `deleteDatabase`，否則會 blocked；或每個 scenario 換新的 `new IDBFactory()`。
   - 四欄複合 unique 在 fake-indexeddb 與瀏覽器皆可行：所有欄位保證是字串（空字串也是合法 key），故不會有「值不是合法 key 而略過索引」的洞；`put` 更新自己不會與自己衝突。`getAll()` 為主鍵升冪，autoIncrement 不重用、`clear()` 不重置，與契約的排序主張一致。
6. **（低，意見）`readWorkbook` 細節補強。** 標題比對建議對標題儲存格也 `trim()`（使用者手改的標題常有空白）；標題不在 Excel 第 1 列時（前面有空白列）`fileRow` 要用實際列號（製片人裁決 2 已說列號用實際 Excel 列號，契約 §3.5 的「以標題列為第 1 列」建議同步改字）；「全空白資料列略過」要寫明是「四格 trim 後皆空」還是「儲存格完全不存在」（features 的「只含空白的儲存格視為留空」其他格有值，不衝突，但全空白格的列行為需寫死）。
7. **（低，意見）`PreviewRow.kinds` 順序未定。** 建議固定為 `IDENTICAL_ROW, SAME_HEAD, SAME_TAIL, SAME_ID_DIFF_NAME`，與 feature 寫法「整列相同、同車頭、同車尾」一致，step 才好比對（或規定以集合比對）。
8. **（低，意見）`noticesForSave` 的邊界。** 編輯時 `SAME_ID_DIFF_NAME` 鍵＝(idNumber, ownerName)：若該身分證底下原本就有 A、B 兩個不同姓名，把 A 改成第三個姓名，鍵有變、仍與 B 衝突，會再通知一次。現有 features 沒有涵蓋，行為可辯護（新的一對衝突），只是記錄。

### SheetJS vendor tgz（採信回報＋我自己確認的部分）
9. **做法可行（事實＋意見）。** `file:vendor/xlsx-0.20.3.tgz` 對 pnpm 11 是直接依賴，lockfile 會記錄 integrity，CI 與重建不依賴 cdn.sheetjs.com；0.20.3 套件本身含 ESM（`xlsx.mjs`）、型別、`sideEffects:false`，可被 Vite 動態 `import()` 與 tree-shaking。npm 的 0.18.5 有 CVE，不可替代，裁決正確。
10. **（低）建議把 tgz 的 SHA-256 記進 `docs/data-contract.md` 或 `vendor/README`**，之後換版時能核對是否被動手腳；上面我算出的雜湊可作為比對基準（我與架構師各自下載，雜湊是否相同由工程部入庫時對照）。
11. **檔頭 PK 檢查（採信回報）**：邏輯正確且必要——SheetJS 會把隨機二進位當 CSV／文字解析而不丟錯，所以 feature「內容是隨機二進位資料的檔案」靠 try/catch 擋不到，須先驗 `50 4B 03 04`。這點我無法獨立重現，但設計方向保守且合理；工程部寫第一個測試時就會驗證。「PK\x03\x04＋雜訊」被 SheetJS 丟錯也是採信，若實際不丟，備援是檢查 `workbook.SheetNames` 非空且第一張表存在。
12. **顯示文字 `cell.w`（採信回報）**：做法正確（預設 `cellText:true` 會產生 `w`，不用 `raw:true`）。風險點給工程部：(a) 要驗證 SheetJS 寫出再讀回，前後有空白的字串（`" 929-X2 "`、`"   "`）是否保留（需 `xml:space="preserve"`），否則情境「前後空白自動去除…」「只含空白的儲存格視為留空」的 fixture 會在 fixture 階段就失真；(b) jsdom 環境下傳入 `Uint8Array` 偶有跨 realm 的 `instanceof` 問題，契約已建議以 `FileReader` 取 `ArrayBuffer`，測試端同樣用 `ArrayBuffer`／Node 的 `Uint8Array` 即可避開。
13. 打包大小未實測（回報已誠實標示）；動態載入且納入 precache 的建議合理。

### 設計方向可實作性（React 19＋Vite、無外部資源、系統字型）
三個方向都可實作：全部是手寫 CSS＋CSS 變數 token，字型皆系統字疊（無字型檔、無授權問題），圖示為內嵌 SVG sprite，無外部資源；亮／暗 token 對比經我重算全數屬實。以下是各自要處理的點，皆非阻擋：
14. **ledger（可實作性最單純）**：宋體疊（Songti TC／Noto Serif TC／PMingLiU→serif）在 Android 會退到 `serif`，字重與觀感會與 macOS 不同，屬預期降級。Dialog 建議用原生 `<dialog>` 或 Radix 的無樣式 primitives；brief 寫的 shadcn Dialog 預設是 Tailwind class，與「全部手寫 CSS」混用要先決定是否引入 Tailwind。「蓋章」旋轉 -1.5° 是 brief 自己提出的待決。
15. **plate**：`content: "頭" / ""`（替代文字語法）在 Safari <17.4、Firefox <128 會讓整條 `content` 宣告失效，**「頭／尾」字樣會消失**，而 brief 的無障礙策略正是靠這兩個字取代顏色。實作時請先寫一條 `content: "頭"` 再寫帶 `/ ""` 的覆寫。另：黃色車尾牌色與 `warn` 黃色相近，brief 已列為待決（營業車黃牌習慣），仍需使用者確認。
16. **signal**：問題跑馬燈只有 hover 暫停，觸控裝置與鍵盤使用者無法暫停，且自動移動超過 5 秒，依 WCAG 2.2.2 需要暫停／停止機制；而它承載「哪裡重複」資訊。實作時需補暫停鈕或 `:focus-within` 暫停，或改為靜態列表（總覽 S5 已有同樣資訊，不構成資訊遺漏）。`clip-path` 切角會裁掉焦點框／邊框，只可用在不可聚焦的訊息框（brief 目前正是如此，請維持）。Magic UI 的 number-ticker／marquee 若要用，需 `motion`＋Tailwind，brief 已說明改手寫（約 6 行 JS），建議維持手寫。
17. 三方向共通：`?theme=` 只是原型機制；實作需決定主題偏好的持久化（`localStorage` 加 `prefers-color-scheme` 預設），並在 `index.html` 以內嵌小段腳本在首次繪製前設定 `data-theme`，避免閃爍。brief 都把「桌面 `<table>` 與手機卡片共用同一份 DOM」留給前端實測無障礙，這點建議在 3 階段先做一個小驗證再定案。
