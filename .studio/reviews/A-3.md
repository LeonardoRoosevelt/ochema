## 問題（退回時）

### 問題 1：Step 無法穩定解析 — 中
**描述**：`excel-import.feature` 的 Outline「CSV 的欄位內含逗號、被引號包住的欄位依規則解析」，其 Then 步驟把含雙引號的姓名直接放進引號字串。
**預期**：每個 step 的 `"..."` 參數可被 step definition 無歧義地取出。
**實際**：
- 該步驟為 `名單上有姓名 "李"美玲"" 的資料，其車頭是 "KLP-7988"`。
- 以 `"([^"]*)"` 或 Cucumber 的 `{string}` 解析，會切成 `李`、`美玲`、空字串，再接 `KLP-7988`。參數個數與內容都錯，step 綁不起來。
- 同一情境的 `"王,小明"` 沒有問題，只有這一行有。
**證據**：`excel-import.feature` 約第 535 行。Given 的 docstring（`"李""美玲"""`）與 export 的資料表（`李"美玲"`）都不受影響，因為不經過 step 參數。
**修復指引**：
- 最乾淨的做法是改用資料表斷言，例如「名單上有以下資料」加一個含該列的表。這與 export 同類情境的寫法一致。
- 或把姓名改成不含引號的描述，例如「姓名為 李美玲 並含雙引號」。
- 不要保留巢狀引號。
**需要改的檔案**：`features/excel-import.feature`

### 問題 2：B-gate 製片人裁決缺少對應情境 — 中
**描述**：B-gate 的製片人裁決有三條是可觀察的確定行為，但增補完全沒有情境，驗收時無從驗證。
- 裁決 2：只有 BOM、沒有任何內容的 CSV 視為檔案是空的。
  - 現有的 CSV 空檔例子只有「內容為 0 位元組」。
  - 這是 0 位元組之外的另一個邊界，也是最容易被實作成「缺標題」或「無法讀取」的案例。
  - 建議在 import 的「完全空白的檔案不接受」Outline 補一列，例如「CSV（只有 BOM）」。
- 裁決 4：CSV 某列欄位少於標題，缺的視為空白，必填則為格式錯誤；多出的欄位忽略。
  - 這是 CSV 獨有的行為，因為 .xlsx／.xls 沒有「欄位數不齊」。
  - 建議補兩個 CSV 情境：少欄的列因必填缺漏成為格式錯誤（原因代碼 `REQUIRED`），多欄的列忽略多出部分照常匯入。
  - 這兩個情境用 docstring 的原始內容寫最直接。
- 裁決 1：畫面預設匯出格式為 .xlsx。
  - 增補的 @ui 情境都明確選了格式，沒有「不選就匯出」的情境。
  - 既有的 @ui 情境「我要求匯出名單」只說 Excel 檔，沒有標示是預設值。
  - 建議補一個 @ui 情境：沒有另外選擇格式直接匯出，取得 .xlsx 檔案。
- 裁決 3（引號內含換行）：已明說不另寫，不算缺漏。
**修復指引**：只補上述情境，不動既有文字。補完後 import 約 +3 個、export +1 個。
**需要改的檔案**：`features/excel-import.feature`、`features/excel-export.feature`

## 建議（不影響放行）
- 低：「各檔案格式完全空白的檔案不接受」Outline 的 `.xls` 列，描述為「完全空白的 .xls 檔」，沒有說是 0 位元組還是有效但無內容的活頁簿。
  - 同列的 CSV 明寫了 0 位元組，兩者不對稱。
  - 回報待決 4 說「真實 .xls 不可能 0 位元組之外的空白」，這個前提不成立，Excel 存出的空白活頁簿並不是 0 位元組。
  - 建議把 .xls 的描述寫明（例如「有效但沒有任何儲存格內容」），0 位元組另列一行，三種格式都比照。
- 低：「各檔案格式的前後空白…」的 Then 在步驟尾端夾了括號註解「（第 2 列去除空白後與既有資料同車頭，被略過）」。
  - 括號內容是說明，不是斷言，step definition 要把它當參數吃掉或忽略。
  - 建議移到註解，或拆成獨立的 And 斷言。
- 低：「隨機二進位資料或損毀的檔案」Outline 的「內容已損毀的 .xls」，沒有定義損毀的位元組長相。
  - 依內容判定規則，若損毀後恰好是合法 UTF-8 文字且無 NUL，會被當 CSV 走，結果是「缺標題」而不是「無法讀取」。
  - 建議說明測試檔以 D0 CF 11 E0 開頭再截斷，使結果穩定。
- 低：export「含特殊字元的姓名」Outline 的 Examples 只列 `.xls` 與 CSV，漏了 `.xlsx`，與其他 Outline 的三格式維度不一致。補一列即可，無風險。
- 低：沒有情境釘住「合法 UTF-8 的純文字檔（非表格）」的結果。依規則會當 CSV 並因缺標題被拒，不是「無法讀取」。這與規則一致，但實作者容易誤判，可在 import 檔頭註明。
