# ochema 資訊架構與關鍵畫面（階段 2b-1）

作者：UX 架構師　日期：2026-11-09
來源：`features/*.feature`（共 49 個 `@ui` 情境，Scenario Outline 算 1 個；另參照 `@api` 情境中與畫面狀態有關的規則）。
範圍：只定結構、狀態、版面策略與「每個方向都必須涵蓋」清單；視覺方向（配色、字體、材質、動態）屬 UI 設計師。

---

## 1. 設計原則（由需求推出）

1. **查詢是首要任務**：開啟 App 就看到搜尋框，打字即時篩選，不需要先點任何東西。
2. **車頭車號、車斗車號最醒目**：使用者要找的是「某台車頭車號／車斗車號屬於誰」，所以車頭車號與車斗車號在每一列都是第一視覺層級，駕駛姓名次之，駕駛身分證再次（但必須完整顯示，不遮罩，見 `search.feature`）。
3. **擋下與警示是兩種不同的事**：車牌格式不合與整列相同＝擋下（資料沒存）；駕駛身分證不合與三種重複＝已存檔但通知。兩者的視覺語意、文案、位置要能一眼區分。
4. **資料只在本機**：沒有帳號、沒有同步、沒有載入遠端資源的畫面；備份提醒要在開啟 App 時就看得到。
5. **不只靠顏色**：所有標示（重複、警示、錯誤）都要有文字或圖形，並可被螢幕閱讀器讀到。

## 2. 資訊架構

### 2.1 頁面與導覽

三個頂層目的地，手機與桌面共用同一組名稱：

| 目的地 | 內容 | 說明 |
|---|---|---|
| **名單**（預設首頁） | S1 名單與查詢、S2 新增／編輯表單、S3 刪除確認 | 80% 的時間在這裡 |
| **總覽** | S5 重複與警示總覽 | 導覽項目上顯示問題數量徽章（有問題時才顯示數字，沒有則不顯示） |
| **資料** | S6 資料與備份（匯出、匯入入口、本機資料說明、外觀主題） | 匯入流程 S4 由此進入 |

導覽形式：
- **手機（< 768px）**：底部分頁列（3 項，含圖示＋文字，高度 ≥ 56px 並避開 iPhone 底部安全區）。「新增」不放進分頁列，另放在名單頁的拇指可及位置。
- **桌面（≥ 768px）**：頂部列左側為 App 名稱，右側為三個目的地連結；主題切換放頂部列最右。

路由概念（供工程參考，不是實作規格）：
```
/            名單（含查詢參數 q）
/record/new  新增表單      （手機為整頁；桌面為對話框，網址可直達）
/record/:id  編輯表單      （同上）
/overview    總覽
/data        資料與備份
/data/import 匯入流程（選檔→預覽→結果，同一路由內切換步驟）
```
- 表單、匯入屬於「任務」，手機上以整頁呈現並有明確的返回／取消；桌面表單以對話框呈現（保留背後名單與查詢），匯入預覽因內容多，桌面也用整頁。
- **查詢條件跨頁保留**：從名單進入表單、總覽、資料頁再回來，查詢關鍵字仍在（`search.feature`「在查詢結果中編輯後，查詢條件保持」）。

### 2.2 全域元件（所有頁面可能出現）

| 編號 | 元件 | 內容與規則 |
|---|---|---|
| C1 | **存檔後通知**（重複／駕駛身分證警示） | 新增或編輯存檔「成功但有問題」時出現。內容：發生的重複種類（可多種並列）、與之衝突的既有資料（至少含車頭車號／車斗車號／駕駛身分證其中衝突欄位的值與駕駛姓名，建議直接列四欄）、駕駛身分證檢查碼不符的提示。**不會自動消失**（內含需閱讀的資料），需使用者關閉；含「到總覽查看」連結。沒有新問題時完全不出現（`新增不造成重複時不顯示重複通知`）。以 `role="status"`／polite 播報。 |
| C2 | **本機資料提示** | 一行常駐說明「資料只存在這台裝置上」＋「請定期匯出 Excel 備份」＋前往匯出的連結。位於名單頁頂部或底部（開啟 App 即可見，不需任何操作），在 S6 有完整版。是否可被關閉見待決問題 Q4。 |
| C3 | **操作結果訊息** | 匯出完成（「已匯出 N 筆資料」）、刪除完成、存檔成功等簡短回饋。可自動消失，但必須同時能被螢幕閱讀器播報、且停留時間 ≥ 5 秒；`prefers-reduced-motion` 下不做滑動。 |
| C4 | **列標示**（重複／警示徽章） | 見 3.1 的「資料列」。 |
| C5 | **版本更新提示**（非 `@ui` 情境，屬選配） | `offline-use.feature` 規定新版本不得自動重新整理。若要讓使用者知道有新版，只能是「有新版本，按此重新載入」的提示，由使用者決定時機。是否做見 Q9。 |

## 3. 畫面規格

下表使用統一的「狀態」詞彙：**預設**、**載入**、**空**、**無結果**、**錯誤**（系統層）、**擋下**（資料沒存的驗證訊息）、**警示**（已存檔的提示）。

### 3.1 S1 名單（首頁）

**用途**：查詢、瀏覽、進入新增／編輯／刪除。

**區塊（由上到下）**
1. 頂部標題列（手機：App 名稱；桌面：整體導覽）。
2. **查詢區**：單一輸入框（標籤「查詢」，說明文字寫明「車頭車號、車斗車號、駕駛姓名、駕駛身分證皆可」）＋清除（×）按鈕＋筆數文字（「符合 N 筆／共 M 筆」）。手機上查詢區黏在頂端（sticky），捲動名單時不消失。
3. **C2 本機資料提示**。
4. **新增按鈕**：桌面在查詢區右側；手機為拇指區的浮動按鈕或底部固定列（UI 設計師擇一，但必須在分頁列之上、不遮擋最後一列）。
5. **名單本體**（資料列）。
6. **C1 存檔後通知**（出現時置於查詢區下方、名單上方，不推走查詢框）。

**資料列（桌面為表格列，手機為卡片）內容**
- 車頭車號、車斗車號、駕駛姓名、駕駛身分證（完整顯示，無遮罩）。
- **重複標示**：有重複的列顯示徽章與種類文字「同車頭車號」「同車斗車號」「同駕駛身分證不同姓名」，可同時多種（`名單上持續標示有重複的資料`）。徽章要說明是哪個欄位的值重複，但不要求在列內列出對方資料（那是總覽的任務）。
- **駕駛身分證警示標示**：駕駛身分證欄位旁圖形＋文字（如「檢查碼不符」），原值仍完整顯示（`名單上標示駕駛身分證有警示的資料`）。警示原因文字依 5.3 的對照表。
- 操作：「編輯」「刪除」。手機卡片上以兩個明確按鈕呈現（≥ 44×44px，不得只靠左滑）；桌面表格列尾兩個按鈕（鍵盤可 Tab 到）。
- 查詢命中的文字建議做**非顏色**的標示（例如底線＋粗細），讓使用者看出是哪個欄位命中。

**狀態**

| 狀態 | 條件 | 呈現 |
|---|---|---|
| 載入 | App 啟動、讀取本機資料庫中（數千筆時可能有感） | 名單區骨架或「載入中」；查詢框可先輸入但不篩選直到載入完成；不阻擋導覽 |
| 空 | 名單 0 筆且無查詢 | 「名單目前沒有資料」＋兩個動作：「新增第一筆」「匯入 Excel」（`名單為空時顯示空狀態`）。C2 照常顯示。 |
| 無結果 | 有查詢但 0 筆符合 | 「查無符合的資料」＋顯示所查關鍵字＋「清除關鍵字」按鈕。**與「空」文案、動作不同**。 |
| 預設 | 有資料 | 名單；篩選時顯示筆數 |
| 重複標示 | 該列在任一重複組 | C4 徽章＋種類文字；重開 App、刪除或編輯後標示依實際資料重算 |
| 駕駛身分證警示 | 該列駕駛身分證有任何 `ID_*` 警示 | C4 警示標示 |
| 錯誤（系統） | 本機資料庫無法開啟或讀取失敗（例如瀏覽器封鎖儲存、無痕模式） | 整區錯誤面板：說明「無法讀取本機資料」、可能原因、「重試」；**不可顯示成空名單**（會讓使用者誤以為資料消失） |

**行為規則**
- **即時篩選**：輸入時（延遲 ≤ 150ms）篩選；**使用中文輸入法組字期間（composition）不篩選**，組字結束才篩選，避免注音未選字時結果亂跳。
- 前後空白忽略、不分大小寫、任一欄位部分符合（`search.feature`）。
- 清除關鍵字後回完整名單，焦點回到查詢框。
- 筆數文字用 `aria-live="polite"` 播報（「符合 2 筆」）。
- 編輯後若該筆已不符合目前查詢條件，列會從結果消失；此時 C3 應告知「已存檔（目前不在篩選結果中）」，見 Q6。
- **資料量**：數百到數千筆。名單必須以虛擬捲動或漸進渲染處理，不用分頁（分頁會讓「查詢」之外的瀏覽成本升高）；實作選擇交給架構／工程，但 UI 不得假設一次渲染全部列。虛擬捲動時仍需讓螢幕閱讀器知道總筆數（`aria-setsize`／文字）。
- 排序：產品範圍明確排除「排序／進階篩選」。預設排序見 Q5。

### 3.2 S2 新增／編輯表單

**用途**：新增一筆或編輯既有一筆（同一個表單，標題不同：「新增資料」／「編輯資料」）。

**區塊**
- 錯誤摘要區（出現時置頂，列出所有擋下的欄位與原因，每項可點擊跳到該欄位；送出失敗時焦點移到此處）。
- 四個欄位，順序固定：**車頭車號、車斗車號、駕駛姓名、駕駛身分證**（與匯出欄序一致）。每個欄位有可見標籤（不只 placeholder）、必填標記（文字「必填」，不只星號顏色）、欄位下方說明、欄位下方錯誤訊息。
- 動作：主要「儲存」、次要「取消」。編輯模式不提供「刪除」（刪除只從名單列進入，避免誤觸；如要在表單內也有，見 Q8）。

**欄位說明文字（常駐，非 placeholder）**
- 車頭車號／車斗車號：「大寫英文或數字，以單一連字號相連，例如 929-X2」
- 駕駛姓名：無格式限制
- 駕駛身分證：「10 碼；格式或檢查碼不符時仍可儲存，但會被標示」

**驗證時機**：送出時驗證（擋下類）。已嘗試送出後，欄位內容改變時即時重驗該欄位並更新錯誤。不在使用者還沒輸入完時就跳出紅字。駕駛身分證警示不在欄位內擋，只在欄位下顯示非阻擋的提示（「檢查碼不符，仍可儲存」），存檔後才進入 C1。

**狀態**

| 狀態 | 條件 | 呈現 |
|---|---|---|
| 預設（新增） | 開啟 | 四欄空白，焦點在「車頭車號」 |
| 預設（編輯） | 從名單列進入 | 預填四欄現值，焦點在第一欄 |
| 擋下：必填 | 任一欄留空或只含空白 | 該欄錯誤「『駕駛姓名』為必填」，資料沒存（`必填欄位留空…`、`只含空白…`） |
| 擋下：車牌格式 | 車頭車號或車斗車號有任何 `PLATE_*` | 該欄錯誤，**必須說明「只接受大寫英文或數字、以單一連字號相連」**（`小寫車牌擋下…`、`車牌中間含空白…`），並依原因代碼補一句具體原因（見 5.1）。不自動轉大寫、不自動修正使用者輸入 |
| 擋下：整列相同 | 與另一筆四欄完全相同（前後空白去除後比對） | 表單層級錯誤（不是單一欄位）：「與既有資料整列相同，未儲存」＋**列出該筆既有資料四欄**（`新增與既有資料四欄完全相同…`、`編輯成與另一筆…`）。表單保持開啟、已輸入內容保留；編輯時原資料不變 |
| 警示：駕駛身分證 | 存檔成功但駕駛身分證有 `ID_*` | 存檔後關閉表單，C1 顯示「駕駛身分證檢查碼不符」等 |
| 警示：重複 | 存檔成功並造成新重複 | 存檔後關閉表單，C1 顯示種類與衝突資料 |
| 儲存中 | 送出後等待寫入 | 儲存按鈕進入處理中狀態並防止重複送出（避免連點新增兩筆） |
| 錯誤（系統） | 寫入失敗（儲存空間滿、資料庫錯誤） | 表單內錯誤區「儲存失敗，資料未變更」＋重試；已輸入內容保留 |
| 取消 | 按「取消」／返回／Esc | 回名單，資料不變（`編輯後放棄修改`）。已有未儲存變更時是否先確認見 Q7 |

**輸入細節（給工程與 UI）**
- 手機輸入框字級 ≥ 16px（避免 iOS 自動放大頁面）。
- 車頭車號／車斗車號／駕駛身分證欄位關閉拼字檢查與自動完成；**是否讓手機鍵盤自動大寫（autocapitalize）屬於商業意圖，見 Q3**。
- 前後空白在存檔時自動去除（`前後空白自動去除後存檔`），存檔後名單顯示去除後的值；不需要額外對使用者說明，但 C3 的存檔成功訊息可顯示存下的值。
- 手機：整頁表單，儲存／取消固定在鍵盤上方或頁面底部，不被虛擬鍵盤遮住。桌面：對話框，焦點困在對話框內，Esc 取消，關閉後焦點回到觸發的按鈕或列。

### 3.3 S3 刪除確認

- 觸發：名單列的「刪除」（或總覽內該筆的刪除）。
- 內容：標題「刪除這筆資料？」，**顯示被刪除那一筆的四欄**（讓使用者確認刪的是對的），說明「刪除後無法復原」（產品範圍明確排除復原）。
- 動作：「刪除」（破壞性樣式，但不能只靠紅色）與「取消」；**預設焦點在「取消」**（`刪除資料前須確認`、`刪除時取消確認，資料保留`）。
- 手機為底部抽屜或置中對話框皆可；兩者都要有焦點陷阱與 Esc／返回關閉。
- 狀態：確認中（防連點）、失敗（「刪除失敗，資料仍在」＋重試）。
- 刪除成功後：C3「已刪除」；重複標示與總覽依剩餘資料重算（`刪除其中一筆後，另一筆的重複標示消失`）。

### 3.4 S4 匯入流程（三步，位於「資料」下）

進入點：S6 的「匯入 Excel」，以及 S1 空狀態的「匯入 Excel」。

#### S4a 選擇檔案
- 一個明確的「選擇 Excel 檔」按鈕（手機會開啟「檔案」App；桌面另可拖放，但拖放只是加分，按鈕必須存在且鍵盤可操作）。
- 說明：檔案需含標題列「車頭車號、車斗車號、駕駛姓名、駕駛身分證」（順序不限）；可先匯出一份當範本（連結到 S6 匯出）。
- 狀態：**解析中**（有進度或不確定進度指示；數千列時可能數秒，需可「取消」）；**檔案不接受**（見下）。

檔案層級的拒絕（不進入預覽、不提供匯入選項，錯誤訊息清楚且可重新選檔）：

| 情況 | 訊息重點 |
|---|---|
| 不是 Excel／無法讀取 | 「檔案無法讀取」，建議確認是 .xlsx |
| 完全空白 | 「檔案是空的」 |
| 缺少欄位標題 | 指出**缺少哪個標題**（例如「缺少欄位標題『駕駛身分證』」） |
| 只有標題列、沒有資料列 | 「檔案內沒有可匯入的資料」；不提供選項與確認按鈕。這與「不接受」不同——檔案本身格式沒問題，需有獨立文案 |

#### S4b 預覽（最重要的畫面）
目標：讓使用者在確認前看懂「每一列會發生什麼」，且在確認前名單完全沒變（`在畫面上預覽並匯入`）。

**區塊**
1. **檔案摘要**：檔名、資料列數（不含標題列）。
2. **分類統計列**（互斥，加總 = 資料列數；畫面上要標出加總以便核對）：
   - 可新增 N 筆
   - 與既有資料重複 N 筆
   - 檔內重複 N 筆
   - 格式錯誤 N 筆
   - 另有一個**橫跨類別的標記**：「駕駛身分證警示」N 筆（只警示，仍留在原本類別，不是第五個互斥類別；見 Q1 對「五類」的確認）
3. **整列相同提醒（單獨區塊，有則顯示在統計列之下、明顯位置）**：列出「整列相同」的列（檔案第 N 列，註明「與既有資料整列相同」或「與檔案第 M 列整列相同」），並以一句話告知「這些列不論選擇『略過重複』或『照樣匯入』都不會匯入」。只是同車頭車號的列不得出現在此（`單獨列出整列相同的列…`）。
4. **各類別明細**：每個類別一個可切換區塊（手機用分段標籤或手風琴，桌面用分頁或並排）。每一列顯示：**檔案第 N 列**（標題列為第 1 列，所以第一筆資料是第 2 列）、四欄的值（以「顯示文字」呈現，前後空白已去除）、以及類別專屬資訊：
   - 與既有重複／檔內重複：**重複種類**（寫法同總覽：列出全部成立的種類；整列相同寫成「整列相同、同車頭車號、同車斗車號」），建議附上是與「既有哪一筆」或「檔案第幾列」重複。
   - 格式錯誤：**錯誤原因**（見 5.1 的文案對照）與是哪一欄。
   - 可新增：若該列駕駛身分證有警示，顯示警示標示。
   預設展開「格式錯誤」與兩種重複類別（使用者需要決定的）；「可新增」預設收合但可展開。數千列時各類別明細需虛擬捲動／漸進載入。
5. **匯入選項（單選）**：「略過重複」「照樣匯入」，各附一句話說明結果：
   - 略過重複：只匯入「可新增」；與既有重複、檔內重複都略過。
   - 照樣匯入：同車頭車號／同車斗車號／同駕駛身分證不同姓名的列也匯入；整列相同的列一律不匯入；格式錯誤不匯入。
   - 兩個選項都另註明「格式錯誤的列不會匯入」。
   - 預設是否預選、預選哪一個見 Q2。未選擇時確認按鈕不可用，並說明原因（不是單純變灰）。
   - 選項旁**建議顯示預計匯入筆數**（例如「預計匯入 12 筆」，隨選項變化）。這需要匯入引擎能在預覽階段算出兩種結果（features 的結果摘要已隱含此計算），屬建議，需架構確認可行（Q10）。
6. **動作**：「確認匯入」（主要）與「取消」（`預覽後放棄，名單不變`——取消後回 S4a 或 S6，名單不變）。

**狀態**

| 狀態 | 呈現 |
|---|---|
| 預覽就緒，有格式錯誤 | 統計列＋格式錯誤明細；仍可匯入其餘列 |
| 預覽就緒，全部可新增 | 其餘類別數字為 0，對應明細區塊顯示「無」，不隱藏（避免使用者懷疑漏掉） |
| 全部都是錯誤或重複（可新增 0 筆） | 仍可預覽；若選項下預計匯入為 0 筆，確認按鈕應提示「沒有可匯入的資料」並停用 |
| 有整列相同 | 顯示提醒區塊 |
| 駕駛身分證警示 | 在明細中標示，並在統計列顯示筆數；說明「警示不影響匯入」 |
| 載入中 | 見 S4a 解析中 |

#### S4c 匯入結果
- 訊息：「已匯入 N 筆、略過 M 筆」；有格式錯誤時加上「格式錯誤未匯入 K 筆」。三個數字一律顯示（0 也顯示），格式與 features 用詞一致。
- 動作：「回到名單」（主要）、「查看重複與警示總覽」（若匯入後總覽有問題才強調）。
- 匯入後名單與總覽依實際資料更新；照樣匯入造成的重複在名單上持續標示（`照樣匯入後，重複的資料在名單上持續標示`）。
- 錯誤狀態：寫入中途失敗時，明確說明「已匯入多少筆」與「未完成」，不可靜默半成功（匯入是否為單一交易由架構決定，見 Q10；UI 需要得知結果才能如實呈現）。
- 同一頁刷新後不重送（避免重複匯入）。

### 3.5 S5 重複與警示總覽

**用途**：集中顯示所有重複與駕駛身分證警示，並可直接處理。

**區塊**
1. 頂部彙總：「共 N 個問題」（重複組數＋駕駛身分證警示筆數）。
2. **重複區**：依種類分三組（同車頭車號、同車斗車號、同駕駛身分證不同姓名）。每個「重複組」是一個項目：種類、重複的值（例如車頭車號 "929-X2"）、涉及 N 筆；展開後列出涉及的每一筆完整資料，每筆有「編輯」「刪除」。同一筆資料可同時出現在不同種類的組中。
3. **駕駛身分證警示區**：每筆有警示的資料一個項目：駕駛姓名、車頭車號、駕駛身分證原值（完整）、警示原因文字；可「編輯」。
- 三個種類用同一套詞彙與標示，與 S1、S4b、C1 一致（`同車頭車號`／`同車斗車號`／`同駕駛身分證不同姓名`）。
- 重複組數與涉及筆數要同時可見（`涉及 2 筆資料`）。
- 與「同一人擁有多台車」無關（同一人同駕駛身分證同駕駛姓名不是重複），不需特別畫面。
- 編輯或刪除後回到總覽（不跳回名單），總覽立即依新資料重算：解除的組消失；三筆同組改掉一筆後剩兩筆仍在，且組的涉及筆數更新為 2。

**狀態**

| 狀態 | 呈現 |
|---|---|
| 無問題 | 「目前沒有重複與警示」＋簡短正向確認（`沒有任何重複或警示時總覽顯示無問題`）；名單為空時同樣顯示（不得出現空白頁） |
| 有重複與警示 | 如上 |
| 只有重複／只有警示 | 沒有的那一區不顯示標題或顯示「無」（擇一，全站一致） |
| 載入 | 數千筆時計算需時間，顯示載入中，不顯示過時內容 |
| 錯誤 | 同 S1 系統錯誤 |

### 3.6 S6 資料與備份

**區塊**
1. **本機資料說明（C2 完整版）**：資料只存在這台裝置；清除網站資料、刪除主畫面圖示可能使資料消失；請定期匯出 Excel 作為備份。（文案細節由內容／UI 決定，但三點必須存在。）
2. **匯出**：標題「匯出 Excel」，說明「一律匯出全部資料，不受名單上的查詢條件影響」，顯示「共 M 筆」，按鈕「匯出全部（M 筆）」。完成後 C3 顯示「已匯出 M 筆資料」，並取得檔案（桌面為下載；iPhone 為分享／儲存選單，細節屬工程）。名單為空時按鈕仍可用，說明「名單是空的，將匯出只有標題列的範本檔」，完成訊息「已匯出 0 筆資料」（`名單為空時在畫面上匯出…`）。
   - **篩選中匯出**：因匯出入口不在名單頁，使用者不會誤以為只匯出篩選結果；但若名單頁帶著查詢條件，S6 的說明仍須明寫「全部」。若 UI 方向要在名單頁也放匯出捷徑，必須沿用「匯出全部（M 筆）」字樣，**不得**寫成「匯出結果」。
   - 狀態：匯出中（數千筆時需指示）、失敗（原因＋重試）。
3. **匯入**：標題「匯入 Excel」＋說明＋按鈕進入 S4a。
4. **外觀**：亮色／暗色／跟隨系統（預設跟隨系統），選擇立即生效並記住（見第 7 節）。
5. **關於**：App 版本與離線說明（可選，無對應 `@ui` 情境）。

## 4. 版面策略（手機與桌面）

### 4.1 斷點（mobile-first）

| 範圍 | 名稱 | 策略 |
|---|---|---|
| 320–767px | 手機 | 單欄、卡片、底部分頁列、整頁表單、可及區在下半部 |
| 768–1023px | 平板／小桌面 | 表格（四欄＋標示＋操作）、頂部導覽、表單用對話框；容器最大 768px 置中或滿寬（UI 擇一） |
| 1024–1279px | 桌面 | 表格＋較寬鬆欄距；容器最大 1024px |
| ≥ 1280px | 大螢幕 | 容器最大 1280px，不再拉寬欄位；總覽可兩欄 |

最小支援寬度 320px（iPhone SE 級）。內容單位用 rem、間距採 4px 網格，細節由前端開發與 UI 設計師的 token 決定。

### 4.2 表格 vs 卡片

- **手機用卡片、桌面用表格**，切換點 768px。理由：四個欄位加上兩種標示與兩個操作，在 < 768px 無法同列顯示而不截斷；而桌面使用者需要掃視比對多列，表格最有效。
- **卡片資訊階層**（由上而下）：車頭車號／車斗車號（最大、可並排，因為都是車牌且長度短）→ 駕駛姓名 → 駕駛身分證 → 標示（重複／警示）→ 操作。標示不可只放在卡片角落的小色點。
- **表格**：使用語意化 `<table>`（`<th scope>`），欄序固定：車頭車號、車斗車號、駕駛姓名、駕駛身分證、標示、操作。欄寬以內容為準，駕駛身分證與車牌採等寬數字風格有利比對（UI 決定）。無排序控制（範圍已排除）。
- 長駕駛姓名（例如含「・」的外國駕駛姓名）換行而不是截斷；車牌、駕駛身分證不得被截斷。
- 同一份資料在兩種版面中的**資訊與操作必須等價**，不得在手機上藏掉標示或某操作。

### 4.3 手機特別注意
- iOS 安全區（瀏覽器下巴、Home 指示條）：底部固定元件需加 `env(safe-area-inset-bottom)`。
- 虛擬鍵盤開啟時，查詢框與表單的儲存按鈕不得被遮住。
- 以「加入主畫面」獨立視窗模式使用：沒有瀏覽器返回鍵，所以每個子頁面（表單、匯入）都要有畫面內的返回或取消。
- 所有可點目標 ≥ 44×44px。

## 5. 文案與對照（供 UI／內容使用）

### 5.1 車牌擋下原因（建議文案，對應 `field-validation.feature` 原因代碼）
所有車牌錯誤都以「車頭車號／車斗車號 格式不合：只接受大寫英文或數字、以單一連字號相連」為共同首句，再補一句具體原因：

| 代碼 | 具體原因 |
|---|---|
| REQUIRED | 「車頭車號」為必填 |
| PLATE_INNER_WHITESPACE | 中間不可有空白 |
| PLATE_FULLWIDTH | 含全形字元，請改用半形 |
| PLATE_LOWERCASE | 含小寫英文，請改用大寫（不會自動轉換） |
| PLATE_INVALID_CHAR | 含不允許的符號 |
| PLATE_NO_HYPHEN | 缺少連字號 |
| PLATE_MULTI_HYPHEN | 連字號只能有一個 |
| PLATE_EMPTY_PART | 連字號前後都要有字元 |

### 5.2 重複種類名稱（全站一致）
同車頭車號、同車斗車號、同駕駛身分證不同姓名；匯入預覽另有「整列相同」。同時成立時並列，不合併成新名稱。

### 5.3 駕駛身分證警示原因（建議文案）
| 代碼 | 文案 |
|---|---|
| ID_CHECKSUM | 檢查碼不符 |
| ID_LENGTH | 長度不是 10 碼 |
| ID_LOWERCASE | 開頭英文字母為小寫 |
| ID_FIRST_NOT_ALPHA | 第一碼不是英文字母 |
| ID_NON_DIGIT | 後 9 碼含非數字 |
| ID_LEGACY_RESIDENCE | 舊式居留證格式 |

警示語氣是「提醒你看一下」，不是「錯誤」；與擋下訊息在圖形、色彩語意、文案上要能區分。

### 5.4 匯入格式錯誤原因
沿用 5.1 的車牌文案；必填缺漏標明欄位（駕駛姓名、駕駛身分證為必填缺漏）；一列多欄有問題時只顯示依欄序第一個不合的欄位與原因（與 features 一致），不要求列出全部。

| 所有操作都不對外發出網路請求 | 全域約束：所有畫面不得載入外部字型／圖示／圖片／腳本，不放外部連結（見第 7 節） |
| 畫面說明資料只存在這台裝置並提醒備份 | C2（S1 常駐）＋S6 完整版 |

覆蓋率：7 + 15 + 2 + 14 + 2 + 3 + 6 = **49 / 49**。

### 非 `@ui` 但畫面必須覆蓋的規則（來自 `@api` 情境，handoff 要求納入狀態）
- 匯入預覽四個互斥類別＋駕駛身分證警示標記＋整列相同提醒（`excel-import.feature` 預覽各情境）→ S4b。
- 檔案層級拒絕：缺標題、空白檔、非 Excel、只有標題列 → S4a。
- 欄位順序與匯出不同仍可匯入 → S4a 說明「依標題對應，順序不限」。
- 取消預覽名單不變（`預覽後放棄，名單不變`，該情境在 feature 中**未帶 `@ui` 標籤**，見回報待決 Q11）→ S4b 取消。

## 7. 全域約束

**無障礙（目標 WCAG 2.1 AA）**
- 鍵盤：所有功能可只用鍵盤完成。Tab 順序與視覺順序一致。對話框有焦點陷阱、Esc 關閉、關閉後焦點回原觸發點。表單送出失敗時焦點移到錯誤摘要。
- 語意：桌面名單用 `<table>`；手機卡片用清單語意（每張卡可被朗讀為「車頭車號 929-X2、車斗車號 20-9A、駕駛姓名 王小明、駕駛身分證 A123456789，同車頭車號重複」）；導覽用 `<nav>`，目前頁面 `aria-current`；頁面有單一 `<h1>`，標題階層連續。
- 動態訊息：查詢筆數、C1、C3、錯誤用 live region 播報；C1 因含內容不自動消失。
- 對比：文字 ≥ 4.5:1、大字與圖形元件 ≥ 3:1；**暗色主題同樣達標**；焦點框明顯且 ≥ 3:1。
- 不靠顏色傳達：重複、警示、錯誤皆有文字或圖形，且三者互相可區分。
- 動態：尊重 `prefers-reduced-motion`；沒有閃爍。
- 觸控：目標 ≥ 44×44px，相鄰目標間有間距。

**離線與外部資源**：字型只能用系統字體或隨 App 打包；圖示用內嵌 SVG 或打包資源；不使用 CDN、不使用需連網才顯示的內容；畫面上沒有外部超連結作為必經路徑。離線下不得出現「請連線」類訊息，也不需要連線狀態指示（見 Q9）。

**主題**：亮色／暗色／跟隨系統三選一，預設跟隨系統；切換立即生效、記住偏好（本機儲存）；避免載入時閃白（首繪前套用主題由工程處理）。切換入口在 S6，桌面頂部列另有快捷。

**效能預算（UX 層面的要求，數字供架構參考）**
- 輸入後 150ms 內畫面更新（數千筆）。
- 啟動到可查詢：離線冷啟動體感 ≤ 2 秒（數千筆時可先顯示查詢框，再填入名單）。
- 匯入預覽解析數千列時要有進度或不確定進度，不凍結介面。

**語言**：全介面繁體中文；數字使用半形；日期若出現用 `YYYY/MM/DD`。

## 8. 給 UI 設計師：「每個方向都必須涵蓋」清單

每個創意方向的 `index.html` 靜態原型（桌面 1440、手機 390 各一張截圖）至少要呈現下列內容，缺一則不算完整方向：

**畫面**
1. S1 名單：有資料狀態，且**同時**包含以下列：一般列、同車頭車號重複列（兩筆）、含駕駛身分證警示的列、同時有重複與警示的列。展開鍵盤焦點樣式的一例。
2. S1 查詢中：有關鍵字、命中標示、筆數文字、清除按鈕。
3. S1 空狀態（0 筆）與無結果狀態（兩者視覺上要可區分）。
4. S2 表單：新增模式含「擋下：車牌格式」錯誤（含完整說明句）與「必填」錯誤並存的一張；另一張「擋下：整列相同」顯示既有資料。
5. C1 存檔後通知：含兩種以上重複並列、衝突資料清單與駕駛身分證警示各一例。
6. S3 刪除確認：顯示被刪資料四欄。
7. S4b 匯入預覽：四類統計＋駕駛身分證警示標記＋整列相同提醒區＋選項區＋明細（至少展開格式錯誤與一種重複類別）。含 S4c 結果。S4a 的四種檔案拒絕訊息可用一張表達。
8. S5 總覽：有問題狀態（三種重複＋警示區皆有項目）與無問題狀態。
9. S6 資料與備份：含匯出、匯入入口、本機資料說明、主題切換。

**狀態與語意**
10. **擋下**、**警示**、**重複標示**、**一般成功**四種訊息語意各有獨立的視覺處理，不得靠單一色相區分，必須各有圖形或文字。
11. 亮色與暗色兩套主題皆要涵蓋（至少 S1 與 S4b 兩張）。
12. 載入與系統錯誤（資料庫無法讀取）各一示意。

**版面與可用性**
13. 桌面表格版與手機卡片版**資訊等價**（見 4.2）；卡片的階層為車頭車號／車斗車號 → 駕駛姓名 → 駕駛身分證 → 標示 → 操作。
14. 查詢框在手機上黏頂；新增與主要操作落在拇指可及區；底部元件避開安全區與分頁列。
15. 完整顯示駕駛身分證（不遮罩）與等寬或表格化的車牌／駕駛身分證，利於比對。
16. 所有點擊目標 ≥ 44px；文字與圖形對比符合 AA（兩套主題）。

**限制**
17. 字型只用系統字或可隨 App 打包的字型（不使用 Google Fonts 等線上來源）；圖示與圖片全部本機。
18. 動態效果（趣味注入師加入的微互動）必須在 `prefers-reduced-motion` 下降級，且不得延遲查詢結果的出現。
19. **每個方向的 brief 必須寫出它刻意不做什麼**（見 frontend-toolkit 創意方向流程第 4 點）。
20. 三個方向要在**概念**上不同，而不只是換色（例：編輯排版感／觸感物件化／動態資料感）；但 1–16 的資訊與結構要求對所有方向一體適用。
21. 不得改動本文件規定的資訊內容、狀態集合、欄位順序與詞彙（同車頭車號／同車斗車號／同駕駛身分證不同姓名／整列相同）；視覺可自由，文案詞彙不可。

## 9. 實作優先順序建議（給前端開發）

1. 設計 token（色彩、字級、間距、斷點、主題三態）與無障礙基礎（焦點樣式、live region、對話框元件）。

5. S6 匯出與 C2。
6. S4 匯入三步（最後做，依賴引擎的預覽結果結構）。
